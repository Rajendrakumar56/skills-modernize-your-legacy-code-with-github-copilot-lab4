# Test Plan — Student Account Management System

## Scope

This test plan covers all business logic in the COBOL Account Management System (`main.cob`, `operations.cob`, `data.cob`). It is written to be implementation-agnostic so that it can be used to validate both the existing COBOL application and a future Node.js re-implementation against the same requirements.

---

## Test Cases

| TC-001 | View balance — initial default balance | Application freshly started; no prior credit or debit performed in the session | 1. Start the application. 2. Select menu option `1` (View Balance). | Balance displayed is `1000.00`. | | | Starting balance is hardcoded to `1000.00` in `DataProgram` (`STORAGE-BALANCE`) and `Operations` (`FINAL-BALANCE`). |
| TC-002 | Credit account — valid positive amount | Application started; current balance is `1000.00`. | 1. Select menu option `2` (Credit Account). 2. Enter `500.00` when prompted. | New balance displayed is `1500.00`; no error message shown. | | | Credit adds the entered amount to the existing balance and writes it back via `DataProgram`. |
| TC-003 | Debit account — sufficient funds | Application started; current balance is `1000.00`. | 1. Select menu option `3` (Debit Account). 2. Enter `200.00` when prompted. | New balance displayed is `800.00`; no error message shown. | | | Debit subtracts the entered amount when `FINAL-BALANCE >= AMOUNT`. |
| TC-004 | Debit account — insufficient funds (overdraft prevention) | Application started; current balance is `1000.00`. | 1. Select menu option `3` (Debit Account). 2. Enter `1500.00` when prompted. | Error message `"Insufficient funds for this debit."` is displayed; balance remains `1000.00`. | | | Core business rule: no negative balances permitted. Balance must be unchanged after a rejected debit. |
| TC-005 | Debit account — exact balance (boundary condition) | Application started; current balance is `1000.00`. | 1. Select menu option `3` (Debit Account). 2. Enter `1000.00` when prompted. | New balance displayed is `0.00`; no error message shown. | | | Boundary: `FINAL-BALANCE >= AMOUNT` is satisfied when they are equal, so the debit must succeed. |
| TC-006 | Debit account — one cent over balance (boundary condition) | Application started; current balance is `1000.00`. | 1. Select menu option `3` (Debit Account). 2. Enter `1000.01` when prompted. | Error message `"Insufficient funds for this debit."` is displayed; balance remains `1000.00`. | | | Boundary: amount exceeds balance by the smallest possible unit. |
| TC-007 | Credit account — zero amount | Application started; current balance is `1000.00`. | 1. Select menu option `2` (Credit Account). 2. Enter `0.00` when prompted. | New balance displayed is `1000.00` (unchanged); no error message shown. | | | Adding zero should be a no-op. Verify system does not crash when a zero amount is entered. |
| TC-008 | Debit account — zero amount | Application started; current balance is `1000.00`. | 1. Select menu option `3` (Debit Account). 2. Enter `0.00` when prompted. | New balance displayed is `1000.00` (unchanged); no error message shown. | | | Subtracting zero should be a no-op. `FINAL-BALANCE >= 0.00` is always true, so the debit path executes and writes back the same balance. |
| TC-009 | Sequential operations — credit then debit | Application started; current balance is `1000.00`. | 1. Select `2`, enter `250.00` (credit). 2. Select `3`, enter `100.00` (debit). 3. Select `1` (view balance). | Balance after step 1 is `1250.00`; after step 2 is `1150.00`; view in step 3 confirms `1150.00`. | | | Validates that the in-memory `STORAGE-BALANCE` is correctly preserved across multiple operations within one session. |
| TC-010 | Sequential operations — multiple credits | Application started; current balance is `1000.00`. | 1. Select `2`, enter `100.00`. 2. Select `2`, enter `200.00`. 3. Select `1` (view balance). | Balance after step 1 is `1100.00`; after step 2 is `1300.00`; view in step 3 confirms `1300.00`. | | | Balance accumulates correctly across consecutive credits. |
| TC-011 | Sequential operations — debit to zero then attempt further debit | Application started; current balance is `1000.00`. | 1. Select `3`, enter `1000.00` (debit to zero). 2. Select `3`, enter `0.01` (attempt debit from empty account). | After step 1 balance is `0.00`. Step 2 shows `"Insufficient funds for this debit."`; balance remains `0.00`. | | | Validates overdraft prevention when balance is exactly zero. |
| TC-012 | Invalid menu choice | Application started. | 1. Enter `5` at the menu prompt. | Message `"Invalid choice, please select 1-4."` is displayed; the menu is shown again without any account change. | | | `WHEN OTHER` branch in `MainProgram`'s `EVALUATE` statement. |
| TC-013 | Invalid menu choice — non-numeric input | Application started. | 1. Enter `A` (or any non-numeric character) at the menu prompt. | Application handles gracefully — either shows the invalid-choice message or re-prompts; balance is unchanged. | | | COBOL `ACCEPT` into a `PIC 9` field; behaviour on non-numeric input is implementation-defined. Node.js re-implementation should document explicit validation. |
| TC-014 | Menu loop continues after each operation | Application started; current balance is `1000.00`. | 1. Select `1` (view balance). 2. Confirm menu is displayed again afterwards. 3. Select `2`, enter `50.00` (credit). 4. Confirm menu is displayed again. | Menu displayed after each completed operation; application does not exit until the user selects `4`. | | | Validates the `PERFORM UNTIL CONTINUE-FLAG = 'NO'` loop in `MainProgram`. |
| TC-015 | Exit application — menu option 4 | Application started. | 1. Select menu option `4` (Exit). | Message `"Exiting the program. Goodbye!"` is displayed and the application terminates cleanly. | | | `CONTINUE-FLAG` is set to `'NO'` and the loop ends; `STOP RUN` is reached. |
| TC-016 | Balance does not persist across sessions | Application run 1: start, credit `500.00`, exit. Application run 2: start fresh. | 1. Run 1: select `2`, enter `500.00`; select `4` to exit. 2. Run 2: select `1` (view balance). | In Run 2 the balance shown is `1000.00`, not `1500.00`. | | | `STORAGE-BALANCE` is in working-storage only; there is no file or database persistence between executions. |
| TC-017 | View balance reflects most recent write | Application started; perform a credit then immediately view balance. | 1. Select `2`, enter `300.00`. 2. Select `1` (view balance). | Balance displayed is `1300.00`, matching the value written by the credit operation. | | | Validates that `DataProgram` `WRITE` and subsequent `READ` return a consistent value within the same session. |
| TC-018 | Large credit amount (field boundary) | Application started; current balance is `1000.00`. | 1. Select `2`, enter `999999.99` (maximum value for `PIC 9(6)V99`). | Balance is `1001000.00` if within the field capacity, or the application handles overflow gracefully. | | | `PIC 9(6)V99` supports a maximum of `999999.99`. The sum `1000.00 + 999999.99 = 1001000.00` overflows the 6-digit integer part; verify overflow handling in both COBOL and Node.js implementations. |

## Notes for Node.js Re-implementation

- TC-013 (non-numeric input) should be handled with explicit input validation returning a clear error message, since JavaScript is dynamically typed and has no native `PIC 9` coercion.
- TC-016 (session-only persistence) should be a decision point: the Node.js app may introduce real persistence (file, database), in which case TC-016's expected result would change and should be re-agreed with stakeholders.
- TC-018 (field boundary) should be replaced with explicit numeric range validation in the Node.js layer instead of relying on implicit field-width truncation.
